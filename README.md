### Hub-Spoke Design Principles I Apply

```
✅  Centralized ingress/egress through Azure Firewall Premium
✅  Private DNS Zones linked to Hub — resolves across all spokes
✅  ExpressRoute / VPN Gateway in Hub only — no spoke-to-on-prem direct
✅  Azure Bastion in Hub — no public IPs on spoke VMs
✅  VNet Peering: Hub↔Spoke only (no spoke-to-spoke direct)
✅  Network Security Groups (NSGs) on every subnet with flow logs
✅  DDoS Protection Standard on Hub VNet
✅  Azure Monitor network diagnostic logs on all Gateway + Firewall
```

### 🔗 Parent → Child Module Calling Pattern

```hcl
# ═══════════════════════════════════════════════════════════════
# main.tf  |  ROOT (PARENT) MODULE
# Calls all child modules — single source of truth for the LZ
# ═══════════════════════════════════════════════════════════════

module "resource_group" {
  source      = "./modules/resource_group"
  name        = "${var.prefix}-${var.environment}-rg"
  location    = var.primary_location
  tags        = local.common_tags
}

module "networking" {
  source              = "./modules/networking"
  resource_group_name = module.resource_group.name
  vnet_name           = "${var.prefix}-hub-vnet"
  address_space       = var.hub_address_space
  subnets             = var.subnet_config
  enable_ddos         = var.environment == "prod" ? true : false
  tags                = local.common_tags
}

module "spoke_networking" {
  source              = "./modules/networking"
  resource_group_name = module.resource_group.name
  vnet_name           = "${var.prefix}-spoke-vnet"
  address_space       = var.spoke_address_space
  hub_vnet_id         = module.networking.vnet_id
  enable_peering      = true
  tags                = local.common_tags
}

module "security" {
  source                  = "./modules/security"
  resource_group_name     = module.resource_group.name
  key_vault_name          = "${var.prefix}-kv-${var.environment}"
  tenant_id               = var.tenant_id
  enable_defender         = true
  enable_sentinel         = var.environment == "prod" ? true : false
  log_analytics_ws_id     = module.monitoring.workspace_id
  tags                    = local.common_tags
}

module "compute" {
  source              = "./modules/compute"
  resource_group_name = module.resource_group.name
  subnet_id           = module.networking.app_subnet_id
  key_vault_id        = module.security.key_vault_id
  vm_size             = var.vm_sku
  enable_autoscale    = var.environment == "prod" ? true : false
  tags                = local.common_tags
}

module "monitoring" {
  source                  = "./modules/monitoring"
  resource_group_name     = module.resource_group.name
  workspace_name          = "${var.prefix}-law-${var.environment}"
  retention_days          = var.environment == "prod" ? 90 : 30
  enable_app_insights     = true
  alert_email             = var.ops_email
  tags                    = local.common_tags
}

module "governance" {
  source              = "./modules/governance"
  management_group_id = var.management_group_id
  environment         = var.environment
  allowed_locations   = var.allowed_regions
  enforce_tags        = true
  enable_budget       = true
  budget_amount       = var.monthly_budget
}

module "dr" {
  source                  = "./modules/dr"
  resource_group_name     = module.resource_group.name
  primary_location        = var.primary_location
  secondary_location      = var.secondary_location
  enable_asr              = var.environment == "prod" ? true : false
  enable_traffic_manager  = true
  tags                    = local.common_tags
}
```

### Terraform Best Practices I Follow

```
✅  Remote State in Azure Blob Storage — container: tfstate
✅  State Locking via Azure Storage Table — prevents concurrent runs
✅  Separate .tfvars per environment (dev / staging / prod)
✅  Dynamic blocks & locals — eliminates code repetition (DRY)
✅  All module outputs chained — zero hardcoded resource IDs
✅  Module versioning via Git tags (v1.0.0, v1.1.0 …) + Terraform Registry
✅  Pre-commit hooks: terraform fmt, validate, tfsec, tflint, checkov
✅  Sentinel policies — block non-compliant resources before apply
✅  Terraform workspaces aligned with Azure subscription boundaries
✅  Variable validation blocks — catch bad input at plan time
✅  Resource tagging enforced via locals.common_tags pattern
```

## 🔄 CI/CD Pipelines — Azure DevOps YAML Best Practices

> I build **separated, purpose-driven pipelines**: Pipeline 1 covers `init → validate → plan` and publishes the plan artifact. A **manual approval gate triggered by PR merge** then releases Pipeline 2 to execute `apply`.

### 🎯 Pipeline Architecture (End-to-End Flow)

### 📄 Pipeline 1 — Validate & Plan (Full YAML)

```yaml
# ══════════════════════════════════════════════════════════════
# azure-pipelines-validate.yml
# PURPOSE  : Terraform init → lint → validate → plan
# TRIGGERS : feature/*, fix/* branches + PR to main
# NOTE     : NO terraform apply here — plan artifact only
# ══════════════════════════════════════════════════════════════
trigger:
  branches:
    include:
      - feature/*
      - fix/*
      - hotfix/*

pr:
  branches:
    include:
      - main

pool:
  vmImage: ubuntu-latest

variables:
  - group: terraform-global-vars          # Variable group in ADO Library
  - name: TF_VERSION
    value: '1.9.0'
  - name: WORKING_DIR
    value: '$(System.DefaultWorkingDirectory)/infrastructure'
  - name: TF_PLAN_FILE
    value: '$(Build.ArtifactStagingDirectory)/tfplan'

stages:

  # ─────────────────────────────────────────────────────────────
  # STAGE 1: Security & Quality Gates (Shift-Left)
  # ─────────────────────────────────────────────────────────────
  - stage: SecurityScan
    displayName: '🔐 Security & Quality Gates'
    jobs:
      - job: IaCScan
        displayName: 'IaC Security Scanning'
        steps:
          - script: pip install checkov
            displayName: '📦 Install Checkov'

          - script: |
              checkov -d $(WORKING_DIR) \
                --framework terraform \
                --output cli \
                --output junitxml \
                --output-file-path . \
                --soft-fail
            displayName: '🛡️ Checkov — Compliance Scan'

          - script: |
              docker run --rm \
                -v $(WORKING_DIR):/src \
                aquasec/tfsec /src \
                --format lovely \
                --soft-fail
            displayName: '🔍 tfsec — Security Scan'

          - task: PublishTestResults@2
            inputs:
              testResultsFormat: JUnit
              testResultsFiles: 'results_junitxml.xml'
              testRunTitle: 'IaC Security Scan Results'

  # ─────────────────────────────────────────────────────────────
  # STAGE 2: Terraform Init → Validate → Plan
  # ─────────────────────────────────────────────────────────────
  - stage: TerraformValidate
    displayName: '🔍 Terraform Validate & Plan'
    dependsOn: SecurityScan
    condition: succeeded('SecurityScan')
    jobs:
      - job: TFValidatePlan
        displayName: 'Init, Lint, Validate, Plan'
        steps:
          - task: TerraformInstaller@1
            displayName: '📦 Install Terraform $(TF_VERSION)'
            inputs:
              terraformVersion: $(TF_VERSION)

          - task: TerraformTaskV4@4
            displayName: '⚙️ Terraform Init'
            inputs:
              provider: azurerm
              command: init
              workingDirectory: $(WORKING_DIR)
              backendServiceArm: $(ARM_SERVICE_CONNECTION)
              backendAzureRmResourceGroupName: $(TF_BACKEND_RG)
              backendAzureRmStorageAccountName: $(TF_BACKEND_SA)
              backendAzureRmContainerName: tfstate
              backendAzureRmKey: '$(Environment).terraform.tfstate'

          - script: |
              curl -s https://raw.githubusercontent.com/terraform-linters/tflint/master/install_linux.sh | bash
              tflint --init
              tflint --format compact $(WORKING_DIR)
            displayName: '🧹 TFLint — Linting Check'

          - task: TerraformTaskV4@4
            displayName: '✅ Terraform Validate'
            inputs:
              provider: azurerm
              command: validate
              workingDirectory: $(WORKING_DIR)

          - task: TerraformTaskV4@4
            displayName: '📋 Terraform Plan'
            inputs:
              provider: azurerm
              command: plan
              workingDirectory: $(WORKING_DIR)
              environmentServiceNameAzureRM: $(ARM_SERVICE_CONNECTION)
              commandOptions: >
                -out=$(TF_PLAN_FILE)
                -var-file=envs/$(Environment).tfvars
                -detailed-exitcode

          - task: PublishPipelineArtifact@1
            displayName: '📤 Publish Plan Artifact'
            inputs:
              targetPath: $(Build.ArtifactStagingDirectory)
              artifact: terraform-plan-$(Environment)
              publishLocation: pipeline
```

### 📄 Pipeline 2 — Manual Approval + Apply (Full YAML)

# ══════════════════════════════════════════════════════════════
# azure-pipelines-apply.yml
# PURPOSE  : Manual approval gate → Terraform apply
# TRIGGERS : Merge to main (trunk) ONLY
# NOTE     : Downloads the saved plan — no re-plan on apply
# ══════════════════════════════════════════════════════════════

  branches:
    include:
      - main

pr: none   # Apply pipeline NEVER triggered by PRs

pool:
  vmImage: ubuntu-latest

variables:
  - group: terraform-global-vars
  - name: TF_VERSION
    value: '1.9.0'
  - name: WORKING_DIR
    value: '$(System.DefaultWorkingDirectory)/infrastructure'

stages:

  # ─────────────────────────────────────────────────────────────
  # STAGE 1: Manual Approval (Human Gate)
  # ─────────────────────────────────────────────────────────────
  - stage: ApprovalGate
    displayName: '⏸️ Manual Approval Gate'
    jobs:
      - job: WaitForApproval
        displayName: 'Awaiting Senior Engineer Approval'
        pool: server                 # Runs on Azure DevOps server — no agent cost
        timeoutInMinutes: 1440       # 24-hour window; auto-reject on timeout
        steps:
          - task: ManualValidation@0
            displayName: '🔐 Senior Engineer Sign-Off Required'
            inputs:
              notifyUsers: |
                senior-devops@company.com
                platform-team@company.com
              instructions: |
                ⚠️  TERRAFORM APPLY IS PENDING YOUR APPROVAL ⚠️

                Before approving, please verify:
                ✅  Review the saved terraform plan artifact
                ✅  Check estimated cost impact (use Infracost report)
                ✅  Confirm all security scan gates passed
                ✅  Validate target environment: $(Environment)
                ✅  Confirm maintenance window is active

                ❌  Reject if any of the above are unsatisfactory.
              onTimeout: reject

  # ─────────────────────────────────────────────────────────────
  # STAGE 2: Terraform Apply (Post-Approval)
  # ─────────────────────────────────────────────────────────────
  - stage: TerraformApply
    displayName: '🚀 Terraform Apply'
    dependsOn: ApprovalGate
    condition: succeeded('ApprovalGate')
    jobs:
      - deployment: ApplyInfrastructure
        displayName: 'Apply Infrastructure Changes'
        environment: $(Environment)   # Links to ADO Environment for audit trail
        strategy:
          runOnce:
            deploy:
              steps:
                - task: DownloadPipelineArtifact@2
                  displayName: '📥 Download Plan Artifact'
                  inputs:
                    artifact: terraform-plan-$(Environment)
                    path: $(Pipeline.Workspace)/tfplan

                - task: TerraformInstaller@1
                  inputs:
                    terraformVersion: $(TF_VERSION)

                - task: TerraformTaskV4@4
                  displayName: '⚙️ Terraform Init (Apply Stage)'
                  inputs:
                    provider: azurerm
                    command: init
                    workingDirectory: $(WORKING_DIR)
                    backendServiceArm: $(ARM_SERVICE_CONNECTION)
                    backendAzureRmResourceGroupName: $(TF_BACKEND_RG)
                    backendAzureRmStorageAccountName: $(TF_BACKEND_SA)
                    backendAzureRmContainerName: tfstate
